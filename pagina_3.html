Proyecto Intermodular

Infraestructura de Red para la Empresa DOSP

SMR2 - IES Chomón - Teruel 2025

1. EXPLICACIÓN

La empresa DOSP es una empresa pequeña dedicada a la fabricación de ruedas para diferentes usos como carretillas o pequeñas embarcaciones.

Actualmente la empresa tiene una infraestructura informática muy básica. Solo dispone de unos pocos ordenadores y no tiene ningún servidor que gestione los usuarios o los recursos de la empresa. Además, la comunicación entre los trabajadores se realiza de forma manual, sin ningún sistema organizado que permita gestionar la información o las tareas de manera eficiente.

Nuestro objetivo es mejorar la organización y el funcionamiento de la empresa mediante la creación de una red local más estructurada. Para ello se implementarán varios servicios de red como DHCP para asignar direcciones IP automáticamente, DNS para resolver nombres dentro de la red y Active Directory para gestionar los usuarios y los equipos desde un servidor central.

También implementaremos un servidor web que permitirá mejorar la presencia de la empresa en internet, creando una página web a la que los clientes puedan acceder.

🎯 Justificación del proyecto

La implementación de esta infraestructura se justifica por las siguientes necesidades empresariales:

  • Centralización de la gestión de usuarios y equipos mediante Active Directory
  • Automatización de la asignación de direcciones IP a través de DHCP
  • Resolución de nombres interna mediante servidor DNS
  • Segmentación de la red en subredes independientes para mejorar la seguridad
  • Presencia online profesional mediante servidor web en DMZ

2. ANÁLISIS Y DISEÑO

2.1. Descripción de las soluciones

Para mejorar la organización de la red de la empresa hemos diseñado una red con varias subredes para separar y organizar mejor los distintos departamentos de la empresa.

El servidor principal será un Ubuntu Server, que actuará a modo de router y permitirá conectar subredes entre sí.

🖥️ Subred de trabajadores

Red: 192.168.10.X

Ordenadores para tareas diarias de los empleados, conectados mediante switch.

👔 Subred del jefe

Red: 192.168.1.X

Dedicada al jefe con acceso a recursos privilegiados de la red.

🗄️ Subred de administración

Red: 192.168.20.X

Recursos compartidos como servidores de datos e impresoras.

🌐 Subred DMZ

Red: 192.168.30.X

Servidor web accesible desde internet de forma segura.

4. IMPLEMENTACIÓN Y DESARROLLO

El servidor web forma parte de la infraestructura del proyecto. Se ha instalado en un servidor Ubuntu ubicado en la DMZ, separado de la red interna para mayor seguridad.

4.2. Asignación de IP fija en el servidor DHCP

Se ha realizado una reserva DHCP en el servidor Linux que funciona como router, garantizando que el servidor web tenga siempre la misma IP sin perder la centralización del servicio DHCP.

🔧 Pasos realizados
  1. Obtener dirección MAC: ip a
  2. Editar configuración: sudo nano /etc/dhcp/dhcpd.conf
  3. Añadir reserva DHCP
  4. Reiniciar servicio: sudo systemctl restart isc-dhcp-server
host servidor-web {
    hardware ethernet AA:BB:CC:DD:EE:FF;
    fixed-address 192.168.30.10;
}

4.3. Instalación de Apache

sudo apt update && sudo apt upgrade -y
sudo apt install apache2 -y
sudo systemctl status apache2
sudo systemctl enable apache2

4.4. Despliegue de la página web

Archivos colocados en /var/www/html/

sudo rm /var/www/html/index.html
sudo cp -r /ruta/web/* /var/www/html/
sudo chown -R www-data:www-data /var/www/html/
sudo chmod -R 755 /var/www/html/
sudo systemctl restart apache2

5. CLIENTE WINDOWS

Se han realizado pruebas desde un equipo cliente Windows para verificar el correcto funcionamiento de todos los servicios de red implementados.

5.1. ipconfig /all

🔍 Verificación de configuración de red

La salida del comando ipconfig /all confirma que el cliente ha recibido correctamente la configuración desde el servidor DHCP:

  • Dirección IPv4 asignada dentro del rango DHCP
  • Puerta de enlace predeterminada apuntando al servidor Ubuntu
  • Servidor DNS configurado correctamente
  • Sufijo DNS del dominio dosp.local

5.2. Pruebas DNS con dig

5.2.1. Zona directa

Las pruebas de resolución DNS directa demuestran que el servidor BIND9 responde correctamente a las consultas, traduciendo nombres como router.dosp.local y web.dosp.local a sus direcciones IP correspondientes. El tiempo de respuesta es inferior a 15ms, lo cual es óptimo para una red local.

5.2.2. Zona inversa

La resolución inversa (de IP a nombre) es fundamental para la verificación de identidad en servicios de red. Las pruebas confirman que el servidor DNS resuelve correctamente las consultas inversas.

6. CONCLUSIÓN

En este proyecto se ha diseñado e implementado una infraestructura de red completa para mejorar la organización informática de la empresa DOSP.

Usando servidores Linux y Windows se han configurado diferentes servicios de red como DHCP, DNS y Active Directory, que permiten gestionar los usuarios y los recursos de la empresa de forma centralizada y organizada.

🎯 Resultados obtenidos

La implementación ha permitido alcanzar los siguientes objetivos:

  • Segmentación efectiva de la red en cuatro subredes funcionales
  • Automatización completa de la asignación de direcciones IP mediante DHCP
  • Resolución de nombres interna funcional con zonas directa e inversa
  • Servidor web operativo y accesible desde la red interna
📚 Valor del aprendizaje

Este proyecto ha consolidado los conocimientos adquiridos en el módulo de Redes, aplicando de forma práctica conceptos de subnetting, enrutamiento, servicios de red y administración de servidores Linux y Windows. La experiencia previa en las FCT del Hospital Obispo Polanco ha resultado especialmente útil para comprender el funcionamiento de redes en entornos reales.
